## Open observations

| # | Observation | Status |

| O1 | Measured with `scripts/measure_latency.py` (five spoken calls, 25 turns, each ending in a committed move): median reply 2.10 s, 95th percentile 3.46 s. A reply after a tool call is 2.15 s median. Parts: waiting to be sure the caller has finished 0.58 s (the voice detector's own 0.55 s silence default, not the endpointing delay), model first word 0.64 s, speech first sound 0.26 s; about 0.6 s was not accounted for by those, until the cause was found: nearly every turn calls a tool (even the name and date-of-birth steps), so the model runs twice per turn, and wait 0.58 + first call 0.65 + second call 0.65 + speech 0.29 is about 2.2 s. Tried: detector silence 0.3 s, endpointing minimum 0.3 s and preemptive generation. The wait fell to 0.39 s but replies did not get faster (median 2.04 s, 95th percentile 3.64 s), so it was not kept. Under a second is the usual target for a phone conversation. | See O14. |
| O2 | In the first voice run the agent marked the appointment confirmed when the caller had only said goodbye. A prompt rule and a behaviour test now cover it, but a prompt is not enforcement. | Closed in Phase 2 (rows 21, 22). |
